# CD volume I cross-identification with PPM and GSC

This report documents the completed cross-identification of the 179,804 entries in the curated first volume of the Córdoba Durchmusterung (CD), zones −22 through −31, against PPM and GSC. It handles single stars, visually double entries, historical colour annotations and a selected sample of large-amplitude variables, using a global exclusive assignment — SCIP for components containing CD doubles, the Hungarian algorithm otherwise.

The method itself, its literature and the general tool interface are documented in [README.md](README.md); this file covers what is specific to this run: the pipeline, catalog preparation, the constants actually fitted, the results and their validation, and the machine-readable format.

The published catalog is **[cd_ppm_gsc.txt](cd_ppm_gsc.txt)**. It contains proposed identifications, **not independently certified astrophysical associations**.

## 1. Pipeline

Run from `likelihood`, with a `python` that has NumPy, pandas, SciPy, Astropy and PySCIPOpt available. The completed run used PySCIPOpt 6.2.1 with SCIP 10.0.2.

```sh
# 1. Rebuild the source union from repository catalogs and prepare hypotheses.
#    Required first step in a clean checkout: writes cd_cross/prepared, plus the
#    calibrated tables and the solver checkpoint under cd_cross/results.
python cross_double_likelihood.py --prepare --build-only

# 2. Solve the saved hypotheses; writes cd_ppm_gsc.txt and auxiliary results.
python cross_double_likelihood.py --solve-only

# 3. Check the published records and compare with PPM's CD designations.
python cross_double_likelihood.py --validate

# Optional: also run the frozen-model sensitivity study and shifted-position control.
python cross_double_likelihood.py --sensitivity

# Optional: re-export the fixed-width catalog without repeating the optimization.
python cross_double_likelihood.py --export-only

# Optional: recalibrate and rebuild hypotheses from cached tables, without solving.
python cross_double_likelihood.py --rebuild --build-only
```

`--data` selects a different prepared/results directory, `--output` the fixed-width catalog, and `--time-limit` the per-component SCIP time limit.

A non-optimal solve **raises an error** rather than publishing an incumbent as an optimum. The checkpoint is a trusted local Python pickle whose input-table SHA256 hashes are verified before loading; do not load untrusted pickles.

### Step 1 inputs

`--prepare` reads the repository's own source catalogs:

| Input | Contents |
|---|---|
| `cat/cd_vol1_curated.txt` | The 179,804 CD records |
| `cat/ppm.txt` | PPM positions, proper motions and photometry |
| `cd/*.txt` | Double (`dpl_*`) and colour (`color_*`) flag lists per zone |
| `gsc/` | GSC region files, decoded in-process |

### Directory layout

`cd_cross` is deliberately minimal: it holds only inputs that no command above can reproduce.

| Directory | Contents | Status |
|---|---|---|
| `cd_cross/variables` | Selected southern GCVS variables (`variables_sur.csv`), selection audit and notes | **Kept** — derived from an external download, not from these scripts |
| `cd_cross/archive` | Pre-consolidation development snapshot | Kept for provenance only |
| `cd_cross/prepared` | Initial CD and PPM/GSC tables, preidentifications, calibration anchors | Generated by step 1 |
| `cd_cross/results` | Calibrated tables, checkpoint, detailed identifications, validation | Generated by steps 1–3 |

Catalog exports for generic single-star matching are in [cat1875/](cat1875/) at this level, not under `cd_cross`. The band-split tables `variables_sur_V.csv` and `variables_sur_otras_bandas.csv` are not stored, being exact `band == 'V'` and `band != 'V'` partitions of `variables_sur.csv`.

### Reproducibility check

The full chain was re-run from a cleared `cd_cross` against the repository source catalogs. It reproduced 34,760 components (34,110 Hungarian, 650 SCIP), every published identification, the same objective, all SCIP solves optimal at zero gap, and a **byte-identical** `cd_ppm_gsc.txt` (SHA256 `3f724221c8a7db99dc8ee6ec00f669b82d9c6e21a47d3e57daed6bb3981b0fd9`). `--validate` returned 40,267 / 40,841 and 0.9873 held-out, matching section 5. Step 1 took about five minutes; step 2, eleven seconds.

Separately, at the time the three current Python files were consolidated, 16 regression tests passed, including exhaustive-oracle checks for SCIP, geometric component routing, variable scatter and normalization, and the generic single-star script reproduced all 31,226 matches of the then-current WB benchmark. Those pre-consolidation experiments are no longer stored; the figures record what the runs found.

## 2. Catalog preparation

CD comes from `cat/cd_vol1_curated.txt`. All original 30-character records are retained, including supplemental and deleted entries. The lists under `cd/` provide the double and colour flags: **1,369 double entries and 739 colour annotations**. Deleted and non-stellar entries are preserved without assigned counterparts. Magnitude code 30 denotes a variable and supplies no numerical photometry.

PPM positions are propagated with proper motion and transformed to FK4, equinox and epoch B1875.0. GSC positions are transformed to the same equinox **without** proper-motion correction. Multiple observations sharing a GSC identifier are consolidated.

For the PPM–GSC preidentification, PPM is first propagated to each GSC object's effective plate epoch, both remaining in a common J2000 equinox for that step. Where an epoch is absent the preparation uses the documented median fallback, approximately 1979.764, and retains a flag. The preidentification is exclusive and uses a calibrated positional cutoff; ambiguous alternatives are recorded for review.

A merged object retains PPM's name, position and photometry, with GSC as an alias; unmerged GSC objects are then appended. The matching population contains **673,661 objects** in a generous declination halo: all prepared PPM objects, plus GSC objects with magnitude at most 13.5, unknown magnitude, or an accepted variable identification. Known variables stay eligible even when measured fainter than the ordinary cutoff. The same population estimates the background density.

PPM's DM designations are interpreted as CD only for zones −23 through −31; zone −22 belongs to SD and is excluded from the reference comparison. Reference labels do not constrain the matching or impose a target PPM/GSC proportion. **Training-sector labels are used in astrometric calibration**, which must be acknowledged when interpreting the agreement in section 5.

## 3. Fitted constants

Angular quantities are arcseconds, densities per square arcsecond. Candidate edges and optimization components use **R = 360″ (6′)** — larger than the 300″ default of the generic tool, and distinct from the 2–80″ pair-separation window below.

The fitted core scales of the positional kernel (README §3.1) are approximately **13.847 for PPM** and **17.297 for GSC**. These are circular Student scales, **not** Gaussian radial RMS values. A smooth tangent-plane offset was fitted on training sectors but **rejected**, because it did not improve held-out median residuals sufficiently; this run therefore applies no fitted positional shift, though the generic single-star method retains the validation-gated correction for other historical catalogs.

Photometric transformations predict CD magnitude separately by source band. The PPM V relation retains the polynomial from `trig.cpp`:

$$
m_{CD}=-0.157169+1.188316\,V-0.022130\,V^2.
$$

| Population | Conversion coefficients, constant first | Base magnitude RMS |
|---|---|---:|
| PPM V | −0.157169, 1.188316, −0.022130 | 0.30 |
| PPM non-V, blank band code | −5.408617, 2.772864, −0.127751 | 0.50 |
| GSC band 0 | 4.897207, 0.395042 | 0.50 |
| GSC band 11 | 6.542284, 0.253155 | 0.50 |
| GSC band 4 | 1.069210, 0.868297 | 0.50 |
| GSC band 6 | 3.999878, 0.533691 | 0.50 |

These GSC codes denote **distinct passbands and must not all be relabelled V**. Exact coefficients, training ranges and validation diagnostics are written to `cd_cross/results/calibration.json` by step 1. Fits use robustly clipped least squares, exclude variable neighbourhoods, and reserve every fifth five-degree RA sector for validation. GSC fits use PPM–GSC anchors rather than indiscriminately fitting faint nearest neighbours. Outside training ranges, monotone linear continuation and increased uncertainty replace unrestricted polynomial extrapolation; unsupported populations fall back to position-only evidence.

The photometric factor's scale is total magnitude RMS divided by $\sqrt{3}$; colour annotations add 0.5 mag in quadrature.

**Prior and pair constants.** The separation density $g$ is normal, truncated to **2–80″**, with mean about 44.186 and scale 15.391. For double-marked entries $p_{single} \approx 0.3651$, and $Q \approx 0.95595$ is fitted from local evidence on ordinary CD entries. No magnitude-contrast term is used in this variant, because the preliminary contrast calibration included chance neighbours. The double search-mass approximation does not exactly integrate loss of the second component at the search boundary.

## 4. Variable stars

The southern GCVS selection requires `declination_J2000 < 0` and `min(m_faint, 13) − m_bright ≥ 2.5`. Unknown intervals, limits and incompatible or unknown bands are excluded. There are **596 selected objects, 385 of them in V**; 46 have numerical extrema marked uncertain, with the flags retained, and five faint extrema are reconstructed from a known bright magnitude and same-band amplitude.

Source: [CDS/VizieR B/gcvs](https://cdsarc.cds.unistra.fr/viz-bin/ReadMe/B/gcvs?format=html&tex=true), downloaded 12 September 2026; the table has 60,894 records and its ReadMe records updates through April 2025. The raw download is not kept — `cd_cross/variables/audit.json` records its URL and SHA256 so the selection can be reproduced from a fresh copy.

Preparation accepted **89 modern-object identifications: 38 PPM and 51 GSC**. The nearest position must be within 5″ and the second neighbour farther than `max(5″, 3 × nearest)`. Candidates out to 30″ are retained in the audit. GSC-only positions remain at plate epoch and GCVS proper motion is not propagated in this tagging step, so missing tags and doubtful identifications remain possible.

Broadening uses the **full** known amplitude, not its value truncated at 13. Independent uniform phases give a magnitude-difference variance $A^2/6$. V extrema are transformed to CD before computing this scatter; other bands use an explicit amplitude proxy with a 1.5-mag CD scatter floor. This is an assumption about phase sampling, not a measured light-curve variance. In the completed assignment, **47 CD entries use a tagged variable counterpart**.

The generic single-star API instead accepts per-epoch scatter directly (README §4.3).

### Sensitivity and negative control

The frozen-model sample is every 100th CD entry plus all double-marked ones: 3,152 rows. It is solved separately, so omitted competing entries can shift its assignments relative to the full run.

| Variant | Assigned | Pairs | Changes from sample baseline |
|---|---:|---:|---:|
| Baseline | 3,036 | 999 | 0 |
| p_single = 0.15 | 3,022 | 1,024 | 41 |
| p_single = 0.75 | 3,036 | 738 | 266 |
| Radius = 180″ | 3,027 | 994 | 9 |
| No variable broadening | 3,036 | 999 | 0 |
| RA shifted by +0.5° | 965 | 144 | 3,088 |

The published run retains the requested 360″ radius. The shifted control's 965 assignments — 30.6% of this double-enriched sample — demonstrate chance-match susceptibility; they are **not** an estimate of the full catalog's false-discovery rate. Likewise, zero changes from variable broadening in this sparse sample does not establish that broadening is irrelevant for all variables.

## 6. Machine-readable format

### Fixed-width catalog

`cd_ppm_gsc.txt` follows the layout specified in `cat/new_format.txt` of Severin (2018), *Cross-identification between Cordoba Durchmusterung catalog (declinations −22, −23 and −24) and PPMX catalog*, Mendeley Data V1, DOI [10.17632/5wwwtv7c8c.1](https://doi.org/10.17632/5wwwtv7c8c.1), CC BY 4.0.

That dataset applied the layout to zones −22 to −24 against PPMX; the present catalog keeps the same **71 ASCII characters per record** plus a newline, and extends the coverage to zones −22 through −31 against PPM and GSC. The first 30 bytes are identical to `cat/cd_vol1_curated.txt`; ordering and all 179,804 rows are preserved. The A19 identifier fields already accommodate both PPM and GSC designations, so no width change was needed.

| Bytes | Format | Units | Label | Meaning |
|---|---|---|---|---|
| 1–2 | A2 | — | prefix | `CD` |
| 3–5 | I3 | deg | zone | Declination zone |
| 6–10 | I5 | — | num | Number within the zone |
| 11 | A1 | — | suppl | Original supplement/corrigendum marker; `D` denotes deletion |
| 12–15 | F4.1 | mag | mag | Original CD magnitude; 20.0 = nebula, 30.0 = variable |
| 16–17 | I2 | h | RAh | Right ascension, 1875 |
| 18–19 | I2 | min | RAm | Right ascension minutes |
| 20–23 | F4.1 | s | RAs | Right ascension seconds |
| 24 | A1 | — | DE− | Declination sign |
| 25–26 | I2 | deg | DEd | Declination degrees, 1875 |
| 27–30 | F4.1 | arcmin | DEm | Declination arcminutes |
| 31 | A1 | — | dpl | `D` for a visually double entry; otherwise blank |
| 32 | A1 | — | color | `C` for a yellow/red annotation; otherwise blank |
| 33 | A1 | — | type | `0`, `1` or `2` assigned modern counterparts |
| 34–52 | A19 | — | star1 | First designation, left-aligned and space-padded |
| 53–71 | A19 | — | star2 | Second designation, or blanks |

For type 0 both designation fields are blank; type 1 uses only star1. Type 2 is allowed **only** for a double-marked CD entry. The historical manual code `X` is reserved but is not emitted by this automated run.

Designations take the forms `PPM 123456` and `GSC 01234-05678`. A PPM designation is reported before GSC; it need not be the positional-primary member of a pair — the CSV retains `astrometric_primary` separately. Uncertain historical double and colour annotations appear here only as their D/C flags, with explicit uncertainty columns in the CSV.

### Supplementary CSV

The solve writes `cd_cross/results/cd_ppm_gsc.csv`, supplementing the fixed-width file with both identifications, original data, GSC aliases, raw angular distance to the first reported counterpart, pair separation, bands, converted magnitudes, variable metadata, costs and review reasons.

`local_probability` is intentionally empty for the robust CD model. `log_odds_vs_empty` and `local_cost_margin` are **scores, not calibrated global probabilities**. The audit details are in `ppm_reference_disagreements.csv`, `variable_identifications.csv`, `summary.json`, `validation.json` and `sensitivity.csv`.

## 7. Limitations and next research steps

1. PPM reference agreement is partly linked to calibration and says little directly about the GSC-only majority. Inspect discrepancies and seek independent checks before treating associations as settled.
2. GSC lacks proper-motion correction in the historical comparison. Epoch fallback, blends, duplicate observations and an incorrect frozen PPM–GSC merge can all affect results.
3. One circular scale and a broad mixture cannot represent all zone-dependent anisotropy, transcription errors or local historical systematics. The selected anchors do not fully characterize extreme tails.
4. Faint-end selection, band differences and photometric extrapolation remain approximate. The clipped photometric ratio is not a fully specified population or selection likelihood.
5. `p_single`, the separation prior and the pair search mass are provisional. The sensitivity study shows double/single classification is **not** stable under all plausible prior choices. The positional-primary mixture models neither blended flux nor a photocentre.
6. GCVS coverage and the positional tagging procedure are incomplete. Uniform phases, other-band scatter proxies and uncertain extrema need star-specific follow-up wherever they influence a decision.
7. Local margins and incremental costs are not globally marginalized posterior probabilities, and the double workflow does not yet recompute a global alternative-solution margin for every association. An empty result may mean insufficient evidence, conflict, exclusion, missing coverage or catalog error.
